# Wargame – procedural RTS map generator

Procedural terrain generator for a **multiplayer (2–4 players) modern-military RTS**.
Current scope: map generation + rendering + RTS camera only (no units/gameplay yet).
The generated `Terrain` object is meant to be consumed by future gameplay and AI code.

## Working with files

- **Prefer Claude Code's built-in tools** (`Read`, `Write`, `Edit`, `Grep`, `Glob`) over shell commands. Read files with `Read`,
  search with `Grep` / `Glob`, change content with `Edit` / `Write`. Don't `cat` / `sed` / `awk` / `echo >` files, and never edit
  source through Python (or other) scripts or `sed -i`: built-in edits are reviewable and fail loudly when the text doesn't match.
  Use `Bash` for what only a shell does (pnpm scripts, git, running the app / Node scripts, screenshots).

## Stack & commands

- TypeScript everywhere, **pnpm** only. Three.js (r186), Alpine.js (UI panel), Vite 8, `vite-plugin-glsl`.
- `pnpm dev` → http://localhost:3000 (port fixed, `strictPort`). Runs `textures:ensure` first.
- `pnpm build` (textures + `tsc --noEmit` + vite build), `pnpm typecheck`, `pnpm preview` (also port 3000).
- `pnpm textures` regenerates all PNG textures (`--force`); `textures:ensure` only writes missing ones.
- Node ≥ 23.6 runs `.ts` directly (type stripping): **imports must use `.ts` extensions**, and only erasable
  TS syntax is allowed (`erasableSyntaxOnly`, no enums/namespaces/parameter properties).
- `public/assets/**` is tracked with **Git LFS** (`.gitattributes`). Textures are generated by
  `scripts/generate-textures.ts` (own PNG encoder, tileable noise, fixed `TEXTURE_SEED`).

## Core rules

1. **Determinism**: same integer seed (0..2^32-1) ⇒ identical map. All randomness goes through
   `mulberry32` / `hash32` (`src/core/rng.ts`). Never use `Math.random()` in generation.
2. **Per-module random streams**: `src/terrain/seeds.ts` → `STAGE = { sea:1, shape:2, detail:3, rivers:4,
   ranges:5, rocks:6, roads:7, cover:8, trees:9, bases:10, rails:12, cities:13, buildings:14 }` (11 retired, never reuse). Each module gets `stageRng(seed, STAGE.x)`.
   **Never renumber**; add new stages with new numbers so other modules' output doesn't shift.
   Render-side cosmetic randomness (tints, shapes) is also seeded (`hash32(seed, salt)` / fixed seeds).
3. Generation is pure TS with no Three.js dependency (`src/terrain/**`) so it can run in Node / workers / server.
4. Heavy Three.js objects must stay out of Alpine reactivity; `engine.generate()` returns a plain `MapInfo`.
5. **Everything drawn must support distance LOD and be cheap far away** — no detail is needed in the distance. Every
   new generated content type gets a near / far representation (mesh `lodMin` / `lodMax`, sprites, simplified far mesh,
   or hidden beyond a distance), and every shader fades its fine detail (patterns under ~1 m, thin lines, extra texture
   taps) to an average colour with `surfaceDetail()` (`shaders/chunks/lod.glsl`) and **skips computing it** beyond the
   range. Sample textures only where their blend weight is > 0 (`textureGrad` with gradients taken outside the branch).
   Shadows follow the same levels (the shadow pass culls with the sun frustum but picks LOD from the main camera); a
   far level that can't cast (sprites) gets a low-poly `userData.shadowOnly` caster. Check a new shader / generator for
   this before calling it done.
6. **Every light source and lit object goes through the `LightField` and gets a far-visibility halo.** Never add ad-hoc
   `THREE.PointLight` / `SpotLight` or a private glow for lamps, windows, signals, flashes, etc.: register `LightDef`s in a
   `LightGroup` (`world.lights.createGroup()`; `group.build(defs, grid)`), which gives the deferred light (or the cheap overlay
   quads on `low`), the light rays for spots and the **light halo** (`lighthalo.*`, a camera-facing disc that stays a few pixels
   wide and fades in with distance, so lit things stay visible when their models / windows are culled). Set the halo range with
   `group.setHaloRange(start, end)` so the halo is at full strength before the near model is culled (halos start *close*: ~0.1x
   to 0.4x of the model's draw distance). Emissive things that don't fit a `LightDef` (e.g. per-window lights) need their own halo
   instances with the same fade (`buildingHalo.vert`). Drive on / off with `group.level` (daylight etc.). See *Deferred local lights*.

## Coordinates

- Grid: play area `256` vertices per side + `pad = 64` cells on every side => `N = size = 384` vertices,
  `cell = 2` world units, `worldSize = 766`, centred on origin. `Terrain.play` = playable square in grid cells
  (`i0..i1`, `j0..j1` = 64..319), `Terrain.playSize = 510` m. Camera bounds = play area.
- **Whole grid is generated the same way** (relief, rivers, roads, buildings, cover, rocks, trees). Only three things are
  tied to the play area: edge mountain ranges (start at the play area border and run outward to the grid edge), bases
  and cities (inside it). Sea coasts are measured from the play area border too (sea fills the margin beyond). River bridges /
  crossing sites are planned inside the play area only. Noise-driven modules (relief, cover, trees) use
  play-area-relative coordinates, so patch sizes don't depend on `pad`.
- Heightmap layout `heights[j * N + i]`; `i` → +X (west→east), `j` → +Z (north→south). World `x = i*cell - worldSize/2`.
- `WATER_LEVEL = 0`, `SNOW_LINE = 80` (shared by generator and terrain/rock shaders; snow patches start ~12 m lower, `SNOW_MARGIN`; snow slides off faces steeper than ~40°). 1 world unit ≈ 1 m. Sides: `north`=j=0, `south`=j=N-1, `west`=i=0, `east`=i=N-1.
- `sampleGrid(h, N, x, y)` = bilinear sample at fractional grid coords.

## Generation pipeline (`src/terrain/pipeline/`; `generate.ts` → `generateTerrain(seed)` drains it)

- `pipeline/run.ts` `runPipeline(seed, opts)`: a JS generator running the stages of `pipeline/stages.ts` in order over one
  shared `GenContext`, yielding `GenEvent`s (`stage`, `meta`, `heights` rows, `rivers`, `bases`, `roads`, `cover` rows,
  `rocks` / `trees` bands, `done` with the full `Terrain`). All plain data, so it can be posted from a worker.
- Chunked stages work in 32-row bands (`GEN_BAND`): relief (centre bands first; per-cell pure), cover, rocks, trees. Modules
  expose band APIs (`buildReliefRows`, `coverBuilder`, `rockScatter`, `treePlanter`); rocks/trees bands run top to bottom so
  the rng stream is consumed exactly as a single pass. **Output must stay bit-identical** to `generateTerrain`.
- Browser: `terrain/worker.ts` runs the pipeline in a Web Worker; `terrain/generator.ts` `TerrainGenerator` posts jobs and
  forwards events (falls back to running on the main thread, one event per macrotask).

| sea | `modules/sea.ts` | 0–3 sea sides with ragged coasts (3 sea sides ⇒ seas narrowed ×0.6 so 4 bases fit) |
| ranges | `modules/ranges.ts` | land edges get mountain ranges with 80% chance (40–65 m at the play border, climbing ×2.2 to a main ridge ~46 m outside it, ~90–145 m, then falling to 10% at the grid edge; shallow saddles: ways out are tunnels) |
| relief | `modules/relief.ts` | base heightmap (smooth, low-frequency, RTS-friendly) + `mountain` field (height added by peaks) |
| blur | `grid.ts` | 2 passes (end of the relief stage) |
| rivers | `modules/rivers.ts` | 1–4 rivers from the grid's outer land edges to sea (or across), via waypoints on the play area border (so they cross it); ends inside a mountain (`mountain` > 5 m) or past the play border on a range side are dropped (a mouth in the sea is kept), so no gorge / slot canyon cuts a range. A dropped head that came down a mountain becomes `River.stream` (world points, `y` = water surface): it springs up to half the mountain's height (grade ≤ 0.6, cutting ≤ 6 m), never rises downstream, eases to sea level at the foot; channels carved after the bank blur (`carveStreams`, `ctx.streamMask`: roads treat it as water, rocks / trees keep off); drawn as water ribbons (`GroundLayer.buildStreams`, water shader with `STREAM`: own surface height, downstream ripples, foam where steep, hidden beyond 900 m). Valley width stops growing above 25 m; carved; returns `mask` (river id+1) and centre `paths` |
| blur | | softens banks (rivers stage) |
| bases | `modules/bases.ts` | 4 player start areas (see below), **levels terrain** inside them |
| cities | `modules/cities.ts` | 0–2 towns (30/45/25%) in contested ground, levelled a little, each with a street grid (see below) |
| roads | `modules/roads/*` | road network (see below), **cuts/fills terrain** under roads |
| buildings | `modules/buildings.ts` | buildings along non-rail roads: dense in towns, hamlets / farms elsewhere; **flat pad** under each (see below) |
| cover | `modules/cover.ts` | dirt amount per cell (~30% of land), grassier near rivers, worn along roads |
| rocks | `modules/rocks.ts` | boulders mostly at mountain feet; avoid roads + base areas; none in snow (top < `SNOW_LINE` − `SNOW_MARGIN` = 24 m) |
| trees | `modules/trees.ts` | one species per map (`pine` / `broadleaf`), forest clumps; avoid mountains, water, roads, rocks, bases |

`Terrain` (`pipeline/types.ts`) fields: `seed, size, cell, worldSize, play, playSize, waterLevel, heights, seaSides, mountainSides, rivers,
bases, cities, roads, buildings, parking, rocks, dirt, mountain, trees, landRatio` (land share of the play area). Generation ≈ 450–650 ms in Node (worker in the browser; the page stays responsive).

### Cities (`modules/cities.ts`)
- Count roll 0/1/2. Site = best score of distance to the nearest base (contested) − 0.35 · distance to the play area centre
  (+ noise), over dry gentle land (SAT); never water, river ±3, mountain > 1.5, base square + 10. Radius 30–44 cells, retried
  at ×0.8 / ×0.65 when it doesn't fit; 2nd city keeps clear of the 1st.
- Shape = noise-ragged disc of usable cells connected to the centre (`cityMask` = id+1). Levelled to its mean keeping 30% relief.
- Street grid: two families of parallel lines `block` (20–26 cells) apart at a random angle, clipped to the shape (streets run
  to the town edge), nodes at crossings and ends; largest connected piece; < 4 streets ⇒ no city there.
- Roads (`growNetwork` step 0): streets are laid first as straight asphalt edges between `junction` nodes (after the base nodes,
  which stay ids 0..3), so ring routes reuse them; each city is then routed (asphalt) to its two nearest bases. Rail keeps out of
  city discs. **No city ⇒ no extra rng draws** (the clean-up passes still apply map-wide).

### Buildings (`terrain/buildings/`, `modules/buildings.ts`)
- `buildingSpec(seed, type)` (`buildings/spec.ts`): pure, own `mulberry32(seed)`; same (seed, type) ⇒ same building. Returns
  footprint (`width` along local X = road, `depth` along local Z = front), `height`, `floors`, `litShare`, colours and `parts`
  (`block` with window grid / doors, `gable`, `hip`, `shed`, `saw`, `slab`, `cylinder`; `detail` parts are near-LOD only) and
  `lights` (gas canopy). Types (`BUILDING_TYPES`): villa (seeded pastel colours, gable/hip/flat roof, garage, porch), apartment
  (3–6 floors, balconies), office (6–12 floors, podium), market (awnings, lit sign), gas (canopy, pumps, kiosk, pylon),
  warehouse (or factory: sawtooth roof, annex, stack), farmhouse, barn (+ silo).
- `Building { id, seed, type, x, y, z, yaw, width, depth, height, floors, condition, city, crane }`: local +Z (front) points along
  (sin yaw, cos yaw), facing its road. `condition` = `intact | abandoned | construction` (left behind: seeded, clustered by
  noise; ~7% town / ~18% rural; half of those, by `hash32(seed, 0xc0b5)` — no rng draw — are unfinished construction sites).
- **Cranes** (`buildings/crane.ts` `planCranes`, end of the buildings module after the pads; pure, seed hashes): 30% of
  construction sites get `crane: Crane { x, y, z, height, jib, counter, heading }` (world; jib along (sin, cos) heading),
  else null. Mast in the tallest block towards its back; of 16 headings the lowest-mast one whose jib + counter-jib beam
  clears the ground by 13 m (trees ≤ ~11 m, lamps, signals), other buildings by 3 m, crosses other beams 3 m above, and never
  passes over another mast / under another beam (else no crane). 100 seeds: 47% of left-behind buildings unfinished, 28%
  of those with a crane, 0 clearance violations, tallest 49 m.
- Placement: (1) one gas station on a road leaving each city; (2) every non-rail edge, both sides: town lots (type by distance
  to the centre: offices/flats core → villas/warehouses rim, 4 tries, last one a villa) or rural lots where the settlement noise is
  high (hamlets) plus rare lone farms (farmhouse + barn). Footprints never cover road mask (tested 1 m beyond the walls, so
  setbacks ≥ 3.2 m), water, river ±2, mountains, base squares + 4; exact rectangle overlap test between buildings.
- Town car parks (`Terrain.parking`, `ParkingLot`): instead of a building lot with 20% chance, 75% right after a market /
  office; 6–12 bays (2.6 m) per row, 16 m deep, entrance gap in the front row; cars are cosmetic (seeded by `lot.seed`).
- Pads: footprint + 1 m yard levelled to its mean, blended over 4 m; never road-levelled (`roadLevel`: road surfaces, junction
  pads, town sidewalks) / base / water cells (car parks too). Footprints
  + a per-type clearing (`CLEARING`: 4–5 m houses / blocks, 7 m gas, 8 m farms, 12 m warehouses) go into `ctx.clear` (rocks,
  trees) along with the whole city mask, so nothing stands inside a wood; cover wears footprint + yard (`builtMask`).

### Town streets (`terrain/urban.ts`, pure, no rng stream)
- `townAt(cities, x, z)`: within 1.25 × City.radius. `planIntersections(t)`: town nodes with ≥ 3 road edges (no rail); each
  approach gets `crosswalk` (distance from the node, clear of the other carriageways), signal `group` (0 = parallel to the first
  approach) and a traffic light `pole` (right of the arriving traffic, behind the stop line). Signals at every 4-way and
  half of the 3-way junctions (hash of seed + node; a 3-way without lights is still an intersection). `signalAt(time, group, offset)` = green 9 s / yellow 2.5 s / red (cycle 23 s),
  same formula as `trafficlight.frag.glsl`; the render clock is `World.update` time (gameplay should drive it from game time).
- Sidewalks are **not geometry**: town asphalt ribbons are drawn wider (`CURB_GAP` 0.2 + `SIDEWALK_WIDTH` 3 m, so they reach
  the nearest building fronts: town setback ≥ 3.2 m) and the road shader paints curb + paving flat on them (`aWalk` = town flag,
  start / end at the crosswalks). Same height, same depth bias.
- Town nodes get a **junction plate** instead of a round cap (`buildPlate` in roads.ts, part of the caps buffer): a polygon
  reaching each arm's crosswalk (or sidewalk edge) with the block corner between neighbouring arms (sidewalk edges' crossing;
  gaps ≥ ~180°, e.g. a T's far side, follow the sidewalk edges and round off, so the fan never folds), painted as carriageway
  inside any meeting road's strip or a disc of its half width round the node (`aJunc` angles, `aJuncW` half widths, up to 4;
  the disc rounds the outer corner of a bend) and curb + paving elsewhere, so corners close up; dead ends get a round turning circle with
  a paved rim (`aWalk.x` 2 / 3). Town ribbons draw only their carriageway (clean edge, no gravel) before the crosswalk.
- Street lights: town streets every 9 m alternating sides on the sidewalk (13 m clear of nodes); elsewhere asphalt 18 m, dirt 30 m.
- `BuildingState` (`buildings/state.ts`): runtime destroyed bits (`Uint32Array`, bit i = `Terrain.buildings[i]`),
  `isDestroyed/setDestroyed/reset`, `onChange`, `version`, `toBytes/fromBytes` (ceil(n/8) bytes) for network sync. Not part of
  `Terrain`; the render layer creates one per map (`engine.buildingState`).

### Player bases (`modules/bases.ts`)
- Always 4 slots (`PLAYER_SLOTS`), clockwise from north-west; renderer colours: red, green, blue, purple.
- Square build area, preferably 80×80 m (half = 20 cells); falls back to 72/64/56 m when land is tight.
  Rule sets (`RULES`) relax slope/buildable share before size; layout score = min(spacing, `TARGET_GAP`=0.4·N) + 4·half.
- Hard exclusions inside a base: water, river (±1 cell, levelling would dam it), mountain > 3 m.
- Fast search via summed-area tables; spread via farthest-point selection (40 random starts).
- Area is levelled to its mean height keeping 25% relief, blended over 8 cells.
- Typical spacing: ≥150 m between closest bases on 90% of maps, median ~196 m.

### Roads (`modules/roads/`)
- `crossings.ts`: plans 2–4 crossing sites per river (narrow, gentle dry banks, straight 3–5 cell approaches).
  **Roads may cross water only inside these corridors**, one road per crossing.
- `sites.ts`: 0–2 map exits at the lowest point of the grid's outer land edges. Where a range stands on the edge (`exitSite`)
  the exit is a **tunnel portal** at its foot instead (first cell inward past the ridge with `mountain` ≤ `TUNNEL_MOUNTAIN` 10 m), reached by a
  straight 8-cell approach (`approachPoints`; routing starts at its end); railway ends too. `RoadNode.tunnel` = true there.
  Carving leaves ground past the portal plane alone and raises a cut-and-cover mound (`TUNNEL_COVER` 7 m over the barrel,
  flaring into the range); the renderer draws headwall + black opening + wing walls (`render/tunnels.ts`, via `UrbanLayer`).
- `network.ts` (A*/Dijkstra on grid via `pathfind.ts`):
  1. **Ring** between bases (slot order, 0→1→2→3→0). Routes reuse existing road (cost ×0.35);
     only off-road stretches become new edges, joined with junctions ⇒ roads merge, never cross.
  2. Exits joined to nearest road.
  3. Rivers with < `MIN_BRIDGES` (2) used crossings get crossing roads (both banks joined).
  4. Disconnected pieces joined to main network (last resort may bridge anywhere).
  - **Dead-end tidy** (`tidyDeadEnds`, after 4, no rng): each dry dead-end junction (town street ends) is linked straight
    on (≤ 18 cells ahead, within 60°; closer than 8 cells anything not behind it) to the nearest valid road: a facing dead
    end ⇒ both streets merge into one re-smoothed edge (close ends at an angle are cut back to where their lines cross); else an end node with < 4 arms, or midway along an edge met at ≥ 35° (dry, outside bases, grade ≤ 0.3, clear of
    other roads). Otherwise dropped if < 15 cells (30 m); repeated for new dead ends. Town dead ends 823 → 264 over 200
    seeds (none < 30 m, none within 16 m of another road).
  - **Close town junctions** (`mergeCloseJunctions`, after the tidy): twin roads between the same town junctions running
    < 7 cells apart (or duplicates) lose the dirt / longer one; junctions joined by an edge < 15 cells (30 m) merge (plates
    and crosswalks would overlap): kept node = fewer roads moved (tie: older id = street grid), the road straight through
    the dropped node takes over the short edge, others are cut back and re-aimed; skipped if > 4 arms would meet. Then
    `dropRemovedEdges` renumbers. 200 seeds: short town junction edges 108 → 16, 5-arm nodes 7 → 0.
  - **Junction normal form** (before shaping / meshes; renderer just draws the data): `dissolveJoins` turns every 2-road
    junction of one type into one continuous edge (window of ±10 points re-smoothed round the old node); a dirt road
    meeting a town street at a 2-road node is first paved up to a dry split point 4 cells beyond the town reach (urban.ts
    `TOWN_REACH`), so the surface change sits outside town. `straightenArms`: every road leaves a 3- / 4-way junction
    as a straight chord for 8 cells (≤ 1/3 of the edge, shortened where the chord would cut water), so plates,
    crosswalks and stop lines (planned from the leaving direction) match the ribbons. Applies map-wide (no rng).
  - Constraints: max grade 0.3 while routing, shore buffer (no road within 1 cell of water outside corridors),
    junctions only on dry ground (`dryAround`), snap to end nodes (never across a bridge), no short dead ends.
  - Ring roads asphalt with 40% chance, everything else dirt.
  5. **Railway** (`rail.ts` picks ends with its own stream `STAGE.rails`, so roads are unchanged): 50% chance on maps
     with ≥ 2 land sides; one line between two land edges of the outer grid (opposite preferred), routed after the
     roads. May bridge any river (incl. shallow banks, `nearRiver`), never the sea or a used road crossing; avoids bases
     (+6 cells), penalises grade (routing max 0.45) and running within 5 cells of roads; steps onto road cells only
     square-ish (`RAIL_CROSS_COS`), dry, ≥ 5 cells from any node. Smoothed once (min radius 10 cells), then split at
     exact road intersections into `crossing` nodes (2 road + 2 rail edges).
- `shape.ts`: smoothing (RDP → Chaikin → resample 1 cell → relax → min radius 3 cells), **never onto water**
  (`blocked`), done once per road *before* junction splits (continuous curves). Surface profile capped at
  0.25 grade (rail 0.07; the railway is profiled end to end and level crossings take its height, `railNodeHeights`);
  bridges = wet runs + 2 abutment points, arched deck (`sin`).
- `carve.ts`: cells under a road surface take the nearest surface point's height; shoulder cells take the strongest
  cut/fill of all shoulders reaching them (so a road shoulder next to a rail embankment doesn't leave a pit); never fills
  water, leaves ground under bridge decks. Rail cuttings/embankments get wider sides. Town asphalt (`townAt` reach) levels
  its full sidewalk width too (+ `CURB_GAP` + `SIDEWALK_WIDTH`), so slopes beside a street don't bury the sidewalks; the
  levelled cells come back as `RoadResult.level` (`ctx.roadLevel`).
- **Intersection pads**: junctions and level crossings get a flat pad at the node height (radius = widest road half-width
  + `PAD_MARGIN` 2 cells, blended over 4 cells), like a small levelled base; every edge meeting there is level for
  pad radius + 1 cells (`shapeEdge` `flat`, pinned in `limitGrade`; shrunk on short edges so the grade limits hold).
- **Bases outrank roads**: `RoadContext.keep` = base build squares. Carving never touches them; road profiles inside a
  base are pinned to the levelled ground. Pin priority (`releasePins`): pad < base ground / node ends; a span between
  pins that can't fit the grade limit gets exactly the grade it needs as an even ramp (rare: node beside a base).
- Output `RoadNetwork { nodes, edges }` in world units: node kinds `base | exit | junction | crossing`, edge types
  `dirt | asphalt | rail`;
  edge `{ from, to, type, width, points[{x,y,z}], length, bridges[{start,end,length,river}] }`.
- `graph.ts` (for AI): `findRoadRoute`, `nearestRoadNode`, `nearestRoadPoint`, `roadNeighbors`, `edgePointsFrom`.
  Rail is not driveable by default (`speed.rail = 0`; trains pass `{ dirt: 0, asphalt: 0, rail: 1 }`); nearest-road
  queries skip rail. Street lights skip rail (poles still keep clear of it).

## Rendering (`src/render/`)

- `engine.ts`: renderer, scene, `THREE.Timer`, lights, texture loading, per-frame culling, `onStats` (fps + drawn chunks),
  `onProgress` (load label + fraction, null when done). `engine.generate` starts the worker at once and streams events into
  the world; resolves `MapInfo` once fully built. `engine.terrain` = finished map only (null while building).
- **Render pipeline** (`render/pipeline/`): `World.push(event)` stores the data in a live partial `Terrain` and queues jobs
  (`stages.ts`: ground → bases → roads → buildings (per chunk) → props (rocks, then trees, band order matters: cosmetic rng) →
  street lights + gas station lights);
  `World.step(BUILD_BUDGET_MS = 6, focus)` runs jobs each frame within the budget (`queue.ts`: by rank, then nearest
  focus; same key replaces). `World.build(terrain)` = load everything at once. After jobs, `Culler.sync` registers new /
  removed / `userData.boundsDirty` meshes. A new map (`meta`) clears the old one; `whenBuilt()` resolves when done.
- `world.ts`: owns all map meshes; layers `GroundLayer` (`ground.ts`: terrain chunks, water, edge skirt, data textures),
  `RockLayer`, `RoadLayer`, `TreeLayer`, `BaseLayer`, `StreetLightLayer` (persistent groups). Rocks/trees: `begin(seed)` +
  `add(band)` (chunk meshes rebuilt with instances appended); roads: `steps()` (per type + bridges). Ground chunks are built
  only when their heights changed and later rewritten in place (fixed topology). Data textures (updated in place):
  half-float heights (water depth), RG8 cover (R dirt, G forest canopy).
- **Culling** (`culling.ts`): Three.js only does per-object sphere frustum culling (no occlusion culling).
  Map is split into 8×8 chunks (`CHUNK_CELLS` = 32 cells = 64 m). Terrain, skirt, rocks (per chunk × shape),
  trees (one InstancedMesh per chunk), road ribbons/bridges (`splitByChunk`) are per-chunk meshes;
  `Culler` tests each mesh's world Box3 against the frustum once per frame. Water plane is excluded
  (`userData.noCull`). All map meshes must have identity transforms: the main `Scene` has `matrixWorldAutoUpdate = false` (three.js'
  per-render world-matrix pass over thousands of meshes was ~1 ms of CPU), so only the two scene lights are updated by hand
  (`Engine.timeOfDay`); anything else that moves needs `updateMatrixWorld()` after each change. The `Culler` buckets items by 64 m ground
  cell and tests a bucket's box once before its items (same result as testing every item).
- **LOD**: `Culler` also honours `userData.lodMin/lodMax/lodCenter` (camera distance to the chunk centre). Terrain chunks
  have 3 detail levels (stride 1/2/4, `TERRAIN_LODS` in `world.ts`); each chunk border has a skirt (duplicated vertices
  pushed down by the `drop` attribute) that hides cracks between levels. Far trees/rocks draw as camera-facing sprites
  (`billboard.ts`): one offscreen bake per species/rock shape at the current camera pitch, re-baked when pitch drifts.
- **Shader detail LOD** (`shaders/chunks/lod.glsl`): `surfaceDetail(p)` = 1 near → 0 between `DETAIL_START` / `DETAIL_END`
  (default 110 / 170 m; a shader may `#define` its own range before the include). Beyond it the fine pattern isn't
  computed, its average colour is drawn: rail (ballast texture, sleepers, rails → mean ballast / 38% timber / 6% steel;
  level crossings show nothing), sidewalk / plate / decal paving (slab joints + texture → `PAVING_AVG`), car-park
  markings; terrain (260 / 400 m: second, fine texture scale dropped; sand / rock / snow sampled only where their weight
  > 0; rock / snow are triplanar on steep faces, `cliffTex`, side taps only where a side has weight), water (220 / 360 m:
  second ripple layer dropped); rocks sample moss / snow only where they show. Road paint has
  its own fade (`MARK_FADE_*`). Far averages are calibrated from the textures' linear means (dirt ≈ 0.06).
- The renderer draws the whole `Terrain` grid (play area + margin) the same way; only the camera is bounded to the play area.
- **Lighting** (`lighting.ts`, `shaders/post.*`): scene renders into an MSAA half-float target with a depth texture; one
  full-screen pass rebuilds world pos from depth and applies a 2048² sun shadow map (ortho, texel-snapped, casters culled by
  the sun frustum but at the **main camera's LOD levels** (`World.cullShadow(lightCamera, camera)`): each object casts with
  the mesh the view draws, off-screen casters still cast; sprites/water/decals flagged `userData.noShadow`; far trees /
  rocks cast through low-poly `userData.shadowOnly` stand-ins (`shadowProxy` in billboard.ts: 6-sided cone for pines,
  20-triangle blob for crowns / rocks, same instance matrices, drawn in shadow passes only)), 14-step screen-space contact shadows and SSAO,
  then does the sRGB output. Shadow share = sun/(ambient+sun) from depth-derived normals, so material shaders are unchanged.
  Depth normals for shading are taken over >= one terrain cell (2 m, central differences, one-sided at depth jumps), so
  the faceted terrain doesn't show its triangles in shadow / AO.
- **SSAO** (`shaders/ao.frag.glsl`, `Lighting.renderAO`): half resolution, 3 small passes before the post pass: depth ->
  linear view depth (R32F), occlusion (`aoSamples` taps, compile-time `AO_TAPS`, view-space reconstruction without
  matrices, 4x4 interleaved rotation, crease bias 0.18), 4x4 depth-aware blur (cancels the interleave). The post pass
  upsamples it with depth-aware bilinear weights. Skipped outside the effect region.
  Effects fade out beyond a region around the camera focus (radius = 0.45 x zoom, 130-200, fading from 75% of the radius). Panel quality select controls it (see Graphics quality).
  Pixel ratio is capped per preset (high 1.25, 2 MSAA samples). Contact shadows are marched only where the shadow map left the pixel
  lit and within 140 m of the camera (faded from 60 m).
- **Soft shadows**: no per-pixel trig / multi-tap kernel. `textures/shadow_noise.png` (64x64, void-and-cluster blue noise made by
  `generate-textures.ts`: rg = cos/sin of a per-texel angle, b = noise value) is fetched once per pixel; the shadow map is then read at 2
  taps (4 on ultra) on opposite sides along that direction, each already a hardware 2x2 PCF. Blue noise spreads neighbouring pixels'
  directions, so the dither reads as a soft edge. The same fetch also gives the AO / contact-shadow jitter.
- **Day/night** (`timeOfDay.ts`): panel slider sets the hour (float 0-24, default 9; `engine.timeOfDay`). `applyTimeOfDay`
  mutates the shared `Environment` in place (sun dir/colour, sky + ground ambient, fog/background, `daylight`), so all
  shaders follow. Sun rises east at 6, sets west at 18, stays north of overhead (shadows fall towards the default camera).
  Sun below the horizon => shadow map and contact shadows are skipped (AO stays, softer). Far-LOD sprites carry baked
  shading, so `World.refreshSprites()` re-bakes them on every change.
- **Street lights** (`terrain/streetlights.ts` `planStreetLights`: pure placement, no RNG; `render/streetlights.ts`): asphalt = tall steel
  poles every 24 m on alternating sides (spot light, warm white), dirt = wooden post with hanging lantern every 40 m (point light).
  Skipped on bridges, near nodes, on banks, near other roads/trees/rocks. One seeded colour per street (`streetIds`: edges
  continuing straight through a junction / level crossing are one street). Town car parks (`planParkingLights`, pure): 7 m poles along
  the lot's back edge (one per ~14 m of width), arm + spot aimed into the lot, one seeded colour per lot (own hash, street colours
  unchanged). One InstancedMesh per chunk and lamp type (culled, `lodMax` 800);
  switched on by daylight (`update(daylight)`: lamp emissive + light dimmer).
- **Deferred local lights** (`lights.ts`, `shaders/light.*`): `LightField` (owned by `World.lights`) holds `LightGroup`s of point/spot
  `LightDef`s. A group is one InstancedMesh of light-volume spheres per chunk (frustum + distance culled by its own `Culler`, `level` dimmer;
  group level 0 = skipped). `Lighting` draws the culled volumes additively (back faces, no depth test) into a half-float light buffer; each
  pixel rebuilds position/normal from the scene depth and writes irradiance. The post pass multiplies it with the surface colour
  (albedo ≈ scene colour / (ambient + sun·n·l)) after sun shadows. No shadows from local lights; needs a quality with the post pass (low draws overlay quads instead).
  New light sources: `field.createGroup()` then `group.build(defs, chunkGrid)`.
  **Light halos** (`lighthalo.vert/frag.glsl`, built with the group in `LightGroup.buildFake`, drawn in the main scene at every quality via
  `field.haloGroup`, own `Culler`): one disc per light, size `max(radius * 0.12, dist * 0.012)`, fading in between `haloStart` / `haloEnd`
  camera distance (`group.setHaloRange`; street / traffic lights 0.08x-0.35x of the lamp draw distance, gas canopies 0.1x-0.4x, building window
  halos 0.12x-0.5x), scaled by the group `level`; a group at level 0 draws none.
  **Signal lights** (`createGroup(true)`, `LightDef.signal = [group, offset]`, `chunks/signal.glsl`): the colour of the light, its halo and
  the low-quality quads follows the traffic-signal clock (red / yellow / green, same formula as `signalAt`); give `color` as white (brightness
  only). The `UrbanLayer` makes one point light per signal pole, on with the street lights. A new light that changes colour over time should
  extend this mechanism (per-instance attribute + time uniform in the vertex shaders), not rebuild the group.
  **Wet-ground reflections** (`lightReflections` quality flag, post pass; `reflect.*.glsl`, drawn into the ray target): one screen-space
  streak per bright thing below it, shown only where `wetmask.ts` (R8, 0.5 m texels) says the ground mirrors: asphalt roads, car parks and
  gas forecourts 1, town sidewalks and paved yards (`urban.ts` `groundPatches`, shared with the decals) less; close-up only (fade 90-150 m,
  grazing view angles). Held in `ReflectionGroup`s: every `LightGroup` has one; lit things that aren't `LightDef`s use
  `field.createReflections(defines, uniforms)` + `add(spots, lodCenter, extraAttributes)` — buildings (`BuildingLayer`, `WINDOW` define,
  `glowSpots`: every window of the lowest 3 floors, lit by `windowLit` in the vertex shader, plus glowing signs; zero matrix = destroyed).
- **Graphics quality** (`quality.ts`, panel select low/normal/high/ultra, default high; `engine.quality`): one `QualitySettings` preset
  drives render scale + pixel-ratio cap, MSAA, the post pass on/off, shadow-map size, shadow-map taps (1 = hard, 2 = soft, 4), contact-shadow steps, AO taps, deferred vs overlay
  lights, billboard (sprite) distance, terrain LOD distance scale, light / lamp-post distance and texture anisotropy. `low` renders at 75%
  resolution straight to the screen (no post pass: no shadows / AO, no MSAA) and replaces deferred street lights by additive overlay quads
  (a camera-facing glow + a pool per light draped over the terrain in the vertex shader from the height texture, `lights.ts` `LightGroup.buildFake`, same culling/instancing). New cost-vs-looks
  High / ultra also draw **light rays** (`lightShafts`, post effect: `ray.*.glsl`): per spot light an instanced bounding sphere (own scene
  `LightField.shaftScene`, chunk-culled by `cullShafts`) is drawn into a half-resolution target; each pixel marches the camera ray (6 steps,
  stopped by the scene depth) through the lamp's cone: a plain translucent cone, opacity linear from lamp (top) to ground (bottom), soft
  at the edge and near the camera (~16 m). The post pass adds the target as is, so roads / trees can't cover it.
  New cost-vs-looks knobs belong in `QualitySettings`. Seed, time of day and quality persist in `localStorage` (`wargame.settings`, guarded) via `main.ts`.
- **Buildings** (`render/buildings/`): `geometry.ts` turns a spec into world-space vertex data; `layer.ts` `BuildingLayer` merges
  per chunk one near mesh (`lodMax` = `QualitySettings.buildingDistance`: windows panes + sills, doors, all details,
  `aWin` = [kind, lit]) and one far mesh (`lodMin`, casts the shadows at its range: boxes + roofs, windows drawn by `buildingFar.frag` from
  `aFacade`/`aGrid` with a glow around lit ones), plus far window halo discs (`buildingHalo.vert` + `lighthalo.frag`) and a
  `LightGroup` for gas canopies. **Windows** are identical in both levels: the far shader rebuilds the near grid (`aCols` =
  first column, columns, wall + 4 * block, floors; `aDoor` for door gaps) and both, plus the halos, light a window with
  `windowLit(key, seed, share)` (`chunks/windows.glsl`): key = (column, floor, wall + 4 * block), seed = `windowSeed(b)`.
  Schedule per window from `env.hour`: never lit (1 − litShare), on 17:30–20:30 (±0.5 h per building), off 21:30–01:30 or
  at dawn 05:00–07:00; glow is also scaled by `lampLevel` (daylight). Keys / seeds use `flat` varyings (interpolation noise
  would change the hash per pixel). Roof decks sit inside parapets (`ROOF_INSET`) to avoid coplanar faces. Abandoned = broken top floor,
  dropped roof, dark / boarded windows, debris (seeded from the building seed). Construction (`buildSite`, `sitePlan` seeded
  once for both levels): per wall block a concrete frame (columns on a 5 m grid, floor slabs up to 40–100% of the floors,
  the top slab partly poured), the crane from `Building.crane`; near adds every column, rebar, a lattice mast, apex, cab,
  trolley + hook and material stacks inside the footprint, far draws slabs, outer columns and the crane as boxes (and
  casts the shadows). No windows / halos / gas lights. **Destruction** is CPU-side: each building's body
  and rubble are vertex ranges of its chunk buffers; `BuildingState` changes collapse / restore them (`addUpdateRange`), so the shadow
  pass (override material) agrees. Street lights keep 1.2 m from building footprints.
- **Road paint** (centre dashes, edge lines, crosswalks, stop lines) is computed in `road.frag.glsl` from per-vertex attributes
  (no paint meshes): it fades out between 140 and 220 m camera distance and is skipped entirely beyond (`MARK_FADE_*`).
- `UrbanLayer` (`render/urban.ts`): **ground decals** (`decal.*.glsl`: flat grids following the ground, same depth bias as the
  roads, drawn after them at renderOrder 0.95, `noShadow`): paving round town buildings (1.5 m + front up to the sidewalk),
  asphalt forecourts under gas stations and car parks (bays, kerb line, entrance) with driveways across the sidewalk to the
  nearest road edge (`toRoad`); parked cars (`lodMax`), traffic lights
  (InstancedMesh per chunk, `aSignal` = [group, offset], lamps lit by the shader from `time`, `lodMax` = lightDistance / 2).
- Instancing: rocks (4 low-poly shapes) and trees (one merged vertex-coloured mesh per species, wind sway
  in vertex shader). Roads are ribbons (3 columns, ragged alpha edges, asphalt lane markings, round caps at
  angled joins, asphalt drawn over dirt via `renderOrder`). Rail = same ribbon with `RAIL` define (ballast, sleepers,
  steel rails), drawn last; at level crossings only the rails are drawn across the road (`railClips`); own bridge style. Bases are draped translucent squares with borders.
- Shaders are separate `.glsl` files imported via `vite-plugin-glsl`. Own chunks: `#include ./chunks/fog.glsl;`
  (with semicolon). Three's built-ins (`#include <tonemapping_fragment>`) are left for Three to resolve.
  Shaders compile as GLSL 3 (WebGL2), so `inverse`/`transpose` are available.
- Fog is custom (uniforms `fogNear/fogFar` scaled by camera distance in `World.update`). Map-edge haze (`fogdist.glsl`) fades
  by `max(|x|, |z|)` over the outer margin, with high ground pulled nearer (0.5 m per m above 20 m) so range summits stay clear.
- `rtsCamera.ts`: edge-pan + WASD/arrows (Shift = fast), Q/E or middle-drag rotate, wheel zoom (25–650),
  focus follows terrain height. Default distance 440.

## Profiler

- `src/core/profiler.ts` (`profiler` singleton, pure TS): categorised CPU scopes (`scope(cat, name, fn)` / `begin` + `end`, self time),
  `pass(name, fn)` for render passes (CPU scope `render/*` + GPU timer query + draw calls / triangles via renderer info), `count(cat, name, v)`
  for sampled values, frame stats (wall / CPU / GPU, worst frames). Everything is one boolean check while not recording, so keep
  instrumentation in. `render/gpuTimer.ts` = `EXT_disjoint_timer_query_webgl2` probe (queries don't nest: only the outermost `pass` queries;
  results arrive late and are tagged with their frame). `renderer.info.autoReset` is off; the frame loop resets it once per frame.
- Instrumented: engine frame loop, every `Lighting.render` pass (shadow map, scene, local lights, rays, AO, bloom, god rays, post, final),
  culling, `World.update` layers, build jobs per kind (`queue.ts`), scene sync, generation events / stage times, atmosphere bake, time of day,
  quality changes. New heavy code: wrap it in a scope (category = subsystem) or `pass`.
- **Detail mode** (checkbox next to the button, default on; `profiler.setDetailed`): `profiler.group(name, fn)` / `part(group, part, fn)` make a
  pass of parts (in detail mode only the parts are timed, as `<group>: <part>`; GPU queries can't nest). Used by `Lighting.drawLayers`: the
  scene and the shadow pass are drawn layer by layer (`World.layerGroups()`, plus halos, overlay quads, sky; an empty render measures the
  per-render overhead, e.g. MSAA resolve, which the report subtracts), and bloom / AO / god rays per full-screen pass (material `name`s).
  `Lighting.drawPost` re-runs the post pass on ~1 frame in 30 per feature with it switched off (`post without: <feature>`): the report's
  A/B section = what each feature costs. Frame times run a little high and the picture flickers on those frames.
- UI: "Record profiler" button (panel); stopping shows the report (environment, frame percentiles, bottleneck verdict CPU / GPU / display-capped,
  CPU by category and scope, GPU passes, counters, slowest frames, hints) in a copyable box.

## Testing / verification workflow

- No test framework. Verify with ad-hoc Node scripts importing `src/terrain/generate.ts` directly
  (e.g. hash `heights`/`roads` for determinism; stats over 100+ seeds). Keep such scripts in the session
  scratchpad, not the repo.
- Screenshots (WSL; MCP chrome-devtools cannot create WebGL here):
  ```sh
  pnpm exec vite build
  (setsid pnpm exec vite preview --port 3100 >/dev/null 2>&1 &); sleep 3
  google-chrome --headless=new --no-sandbox --use-angle=swiftshader --enable-unsafe-swiftshader \
    --window-size=1400,850 --virtual-time-budget=8000 --screenshot=out.png http://localhost:3100/
  fuser -k 3100/tcp      # stop preview; do NOT use pkill -f (kills the calling shell)
  ```
  To view a specific seed/spot, temporarily edit the default seed in `src/main.ts` and
  `reset()` target/distance in `rtsCamera.ts`, then **restore them** (seed 42, target 0,0,0, distance 440).
  Headless screenshots cut the canvas at ~763 px height – a screenshot quirk, not a bug.
- Determinism check after generator changes: hash `generateTerrain` output (heights, dirt, mountain + JSON of the rest)
  for ~200 seeds before and after; also check the streamed events (`runPipeline`) rebuild the same `Terrain`.
- Mid-load screenshots need real time (virtual-time screenshots only show the settled page): drive headless Chrome over
  CDP (`--remote-debugging-port`) and `Page.captureScreenshot` while loading; use `low` quality (swiftshader is slow).
- Useful health metrics: bridges per river, road connectivity (`findRoadRoute` from node 0), off-bridge road
  points over water (must be 0), max road grade, min turn radius, terrain poking above road surface,
  base spacing / flatness, trees on mountains (must be 0), buildings over water / on roads / overlapping / with trees or rocks
  inside (all 0), city count distribution, gas stations per city, maps without cities keep identical roads.

## Known limitations / ideas

- ~14% of rivers get < 2 bridges (no valid crossing site in the play area, or bank can't reach the network).
- 3-sea-side / small-land maps can have bases as close as ~90 m.
- Whole-map view draws ~300 chunk meshes (draw calls); could use larger chunks or LOD for far trees.
- No occlusion culling (not worth it for a top-down RTS camera).
- Towns are compact (median ~17 buildings, 2–4 blocks); lots are only along street fronts, block interiors stay open.
- ~1/3 of cities get no gas station (no free lot on a road leaving them). Rail lines avoid cities, so a railway crossing no
  road (isolated in the graph) is a bit more common (~8/63 rail maps vs 3/67 before cities).
- Touchpad camera rotation not implemented (suggested: two-finger drag with modifier / pinch).
